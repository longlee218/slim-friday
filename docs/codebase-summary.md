# Codebase Summary

Last updated: 2026-10-25 (after web plans 1-6, durable runs and owner and bot communication). Design: 2026-10-23-friday-team-engine-design.md, web app, durable runs.

Friday is a self-hosted personal agent on the Claude Agent SDK (Bun + TypeScript + SQLite/Drizzle). The engine lives in packages; `src/` keeps only the boot.

| Folder | Holds |
|---|---|
| `packages/core/` | domain types, ports, routing, permission decision, bot hub (intake), `runs/` (durable runs: claim, lease and fence, steering, cards, stop, outcome reconciler; run kind, run output and silence, progress budget, nudges, taint, reply guidance), `permission/` (decide, owner rules, taint and name risk, Auto Review step), `hub/` (intro run, teammate directory, scratchpad block), `runs/silent-reply.ts` (no dependencies; tests with fakes in `packages/core/test/`) |
| `packages/runtime-claude/` | `AgentRuntime` on the Claude Agent SDK: streaming session, event mapper, SDK options, hard floor check; `session/` helpers (prompt blocks, current time, call guard, PreToolUse and PostToolUse hooks, tool search, run-kind tools); `review/` (Auto Review one-shot Haiku call and prompt); `floor/` = OS sandbox, env scrub, sensitive paths (tests with a fake `query`) |
| `packages/store-sqlite/` | engine db (conversations, messages with files, run steps and `wake_id`, `scratchpad` items, uploads, files, read positions, grants (with `effect` and `match_kind`), sessions, spend, audit (with `review`), wakes (with `intro` and `nudges`) and run attempts, steering, cards, effect calls, scopes, tickets and their events, better-auth tables) on Drizzle with its own migrations |
| `packages/config/` | file config: bots, groups, settings, tool annotations; schemas, merge with defaults, live reload; `defaults/` (incl. the Friday bot) and `templates/` (three groups) |
| `packages/contracts/` | oRPC contract, zod DTOs, `FridayEvent`, limits; the only code the web app and the API share (imports `@orpc/contract` and `zod` only) |
| `packages/api/` | Hono app and oRPC router: `/api/auth/*` (better-auth, magic link, passkey), `/rpc/*` (owner session, `Origin` check), `/health`; routers for approval rules, permissions (Auto Review), bot scratchpad, conversations, chat, approvals, questions, control, tickets, ops, memory, events and config (bots, groups, avatars, owner files, skills, MCP) over the core ports incl. `ConfigAdmin`, `SkillAdmin`, `MemoryAdmin`, `McpProbe` |
| `packages/surface-web/` | `WebSurface` implements `Surface`: event bus (replay of 500 events), approval and question cards, run steps, owner uploads into `inbox/`, `PostFile` through `FileStore`; no HTTP code |
| `packages/store-r2/` | `R2FileStore` implements `FileStore` over `Bun.S3Client` (Cloudflare R2): put, stat, read, delete, local presigned PUT and GET URLs |
| `packages/tools/` | built-in tools as per-session MCP servers: file memory (`FileMemory`), journal, search, memory tools; effect tools (`DeletePaths` + trash, `GitPush`, `CreatePullRequest`, `MergeBranch`, `CreateProject`); `chat` server (`PostFile`, `PostUpdate`, `UpdateProfile`, `SendToBot`, `HandOff`, per run kind); `scratchpad` server (`ScratchpadList`, `ScratchpadAdd`, `ScratchpadUpdate`, `ScratchpadComplete`, `ScratchpadRemove`); `clip-result.ts` (12 000 chars); `admin/` (the settings admin ports behind the API: config, skills, memory, MCP probe); `tickets` server (`TicketList`, `TicketGet`, `TicketCreate`, `TicketUpdate`, `TicketComment`) |
| `packages/memory-honcho/` | optional memory provider plugin: Honcho v3 client (`fetch`, bounded), URL rule, `honchoSource` (`RecallSource` with write/forget), `honchoPlugin` (imports core only) |
| `packages/computer-cua/` | computer provider plugin: drives the `cua` CLI (argv, no shell, minimal env, `DO_NOT_TRACK=1`) for a bot's Linux computer: create/start, exec, launch, screenshot, input, port-forward, Docker capacity; `cuaPlugin` (imports core only) |
| `packages/api/src/computer/`, `packages/api/src/routers/computer-router.ts`, `packages/core/src/computer/` (control, resume), `apps/web/src/components/computer/` | live view and control (not verified live): `view-proxy.ts` (`/computer-view/<token>/*`, HTTP and WebSocket relay to the loopback Cua viewer, revoke), `view-token.ts` (HMAC link: computer, botId, port, mode, iat, exp), `computerRouter` (status, view, takeControl, renewControl, giveBack, closeView), `computer-control.ts` (owner input hold), `computer-resume.ts` (wake bots the owner turned away), web Computer panel (view frame, take control, give back) |
| `apps/friday/` | composition root: `startApp` (config, db, memory, `WebSurface`, gate, hub, conversation sync, reload, journal prune), `startEngine` (R2 file store, Claude runtime with MCP servers, memory flush, the API server on `127.0.0.1:API_PORT`), `sessionTools`, Friday bot dirs |
| `apps/friday/src/` (additions) | `auto-reviewer.ts`, `permissions-admin.ts` (text edit of `settings.yaml`), `secret-values.ts`, `config/owner-time-zone.ts`; depends on `tldts` for registrable domains |
| `apps/friday/src/workers/` | supervisor and worker processes: spawn and restart, IPC protocol (hints, live events, saved tickets, surface calls), worker app, worker process groups; `limits.workers: 0` runs the same code in the main process |
| `packages/core/src/schedules/`, `apps/friday/src/schedules/`, `packages/tools/src/schedules/` | scheduled runs: schedule model and next-run (core), ticker, fire, reconcile, notices, retention (engine), `ScheduleCreate/List/Update/Delete` tools; plus the `schedules` contract area (`packages/contracts`), router (`packages/api/src/routers/schedules`), SSE `schedule` event, message tag columns and web screens (`apps/web/src/components/schedules`); see [system-architecture.md](system-architecture.md#scheduled-runs-engine-chat-tools-api-and-web) |
| `apps/web/` | the PWA (Vite, React 19, Tailwind 4, Base UI): chat, tickets, ops and settings; imports only `@friday/contracts`; Vitest and a Playwright smoke; `csp/` (`buildCsp`, build-time `<meta>` CSP, `check-dist.ts`), `vercel.json` (static security headers) |
| `apps/friday/src/index.ts`, `apps/friday/src/lifecycle/` | process entry, boot checks, main lock (`main-lock.ts`), trash, upload and home-retention sweepers |
| `apps/friday/src/config/`, `apps/friday/src/observability/` | env and home paths (the only place that reads env besides `apps/friday`), pino logger |
| `docs/ports/` | one page per port: interface, fake, steps to add an adapter |

Root tests are in `test/` (boot, startup, scan tests); each package has its own `test/`. Scan tests: package boundaries, `web-boundary` (`apps/web`), `no-console`, `no-process-env-outside-config`, `no-sql-outside-storage`, `child-env-deny`, `retired-naming-scan`, `publish-scan`.
