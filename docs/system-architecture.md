## Now
- `bun run start` loads config, opens the old SQLite db, runs startup hygiene, starts the trash and home-retention sweepers, then runs the engine (`startEngine` in `apps/friday/src/main.ts`): it refuses by name (`DISCORD_TOKEN missing`, `DISCORD_GUILD_ID missing`, `OWNER_DISCORD_ID missing`) before any network call, connects to Discord, builds `ClaudeRuntime` and `startApp`, logs `engine.started` and runs until SIGINT / SIGTERM (then `app.stop()`, the Discord client closes, the sweepers stop).
- Leftover pieces (plan 7 removes them; the memory helpers and the trash moved to `packages/tools`, the old paths re-export them): policy guard and risk classes (`src/policy`), the old effect tools (`src/effects`, `src/mcp/effects`), the old memory tools (`src/memory`, `src/mcp/memory`), presets as files (`config/presets`, `src/presets`), Playwright and Firecrawl MCP, owner approval (`src/owner-approval`), i18n. None is wired to the new engine yet.
- Removed: chief-of-staff / worker / goal / plan engine, the old Discord surface, artifacts store and viewer, ops dashboard, dreaming and episodes.

## `packages/core` (plan 2)
Domain, ports and use cases; no dependencies, imports only itself (`packages/core/test/core-boundary.test.ts`). Ports are in [`packages/core/src/ports/`](../packages/core/src/ports/): `AgentRuntime` (+ `BotSession`, generic `RuntimeEvent`), `Surface`, `Store`, `ToolCatalog`, `Memory`, `Clock`.
- **Routing** (`routing/`): `@name` parsing; direct chat goes to its bot, a group message to the mentioned members or the entry bot, a bot reply only to bots it mentions. `ChainGuard` caps hops, bot messages per hour and bot repeats.
- **Permission** (`permission/`): `decide` is pure: hard-floor deny, tool override, matching grant, then the autonomy level (careful / balanced / autonomous) for the tool's class from its annotations. Unannotated = ask; irreversible = ask always (no "Always allow"). `PermissionGate` asks through the `Surface`, stores grants, audits, and denies on timeout.
- **Hub** (`hub/`): `BotHub` keeps one session per active bot, pushes one turn at a time (a message to a busy bot waits for the turn to end), turns mentions into hand-offs, applies the daily spend cap, closes idle sessions, resumes after a crash, and serves `stop` and `status`.
- Defaults: `packages/core/src/config-defaults.ts`.

## `packages/store-sqlite` and `packages/config` (plan 4)
Bots and groups are files; the db holds the rest. `apps/friday` joins them: `{ ...engineStore, bots, groups: config.groups }` is the core `Store` (the Friday bot gets its real dirs filled in).
- **Engine db** (`store-sqlite`): `openEngineDb(file)` (WAL, owner-only file and sidecars, refuses a db with tables but no migration log) and `openEngineStore(file)`: tables `conversations`, `messages`, `grants`, `sessions`, `spend`, `audit` (Drizzle schema in `src/schema/`, migrations generated into `src/migrations/` by `bun run db:generate:engine`). `messages.recent` = last N oldest first; `grants.list` = the bot's grants plus `*`; `spend.add` increments. Imports only core, drizzle, `bun:sqlite`, node (`test/boundary.test.ts`). The old `src/storage` db (`data/agent.db`) is still opened by the boot for the sweepers; the engine uses `data/engine.db`.
- **Config dir** (`config`): `bots/<id>.md` (YAML header: name (one word), title, model, tools, skills, subagents, workspaces, autonomy; body = instructions), `groups/<id>.yaml` (name, members, entryBot), `settings.yaml` (autonomy level, per-bot levels, per-tool outcomes, limits over the core defaults), `tools.yaml` (tool annotations). `mcp.yaml` (external MCP servers), `settings.yaml` also holds `projectsDir`. Shipped defaults in `packages/config/defaults/` (annotations of the built-in SDK tools, the read-only Playwright tools, the memory and effect tools; Playwright in `mcp.yaml`; level `balanced`); the user dir wins by id / tool name.
- **Bad files:** each file is parsed alone; one that fails is listed in `problems` with its path and the rest loads. On a reload a file that fails but parsed before (a half-written save) keeps its last good copy. Files with the wrong extension (`.yml`), a typo'd `autonomy.bots` key, and limits a timer or query cannot use (fractions, over 2^31-1 ms) are reported too. After the merge a bot with a repeated name and a group naming a missing bot are dropped with a problem.
- **Live:** `FileConfig` serves bots, groups, the tool catalog, `settings()` and `limits()` from the current snapshot; `reload()` swaps the snapshot in one assignment and returns the changed or removed bots (they get a fresh session); `watch()` reloads on file changes (debounced). A failed reload keeps the last good snapshot.
- **Not built:** retention of messages and audit.

## `packages/runtime-claude` (plan 3)
`AgentRuntime` on the Claude Agent SDK. Imports only `@friday/core`, the SDK and node (`packages/runtime-claude/test/boundary.test.ts`); never reads `process.env` (the caller passes the env).
- **Session** (`session/`): one long-lived streaming `query()` per bot; `ClaudeRuntime.open` returns at once with a UUID it hands the SDK as `sessionId` (it does not wait for `init`), `resume` passes `resume`. `send` pushes a formatted turn (`format-turn.ts`) into the input queue; `events` maps SDK messages (`map-message.ts`): bot text, `task_started`, `task_done` (completed / failed / stopped), `turn_end(cost)`, `error`. An error result is never a `turn_end`; a stream failure throws from `events`; `stop()` closes the input, aborts the SDK and ends `events`.
- **Options** (`build-options.ts`): `settingSources: []`, permission mode `default`, subagents as `background: true` agents, the bot's workspaces as cwd and extra dirs, a scrubbed env that does NOT set `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS`, the OS sandbox, a PreToolUse hook and `canUseTool` that both apply the hard floor first (the CLI auto-allows reads inside the bot's dirs without calling `canUseTool`, the hook covers them); `resume` throws when the SDK has no transcript left (the hub then opens a fresh session). The floor (`floor-check.ts`: file tools outside the bot's dirs, inside the agent home or on a sensitive file are denied and `decide` is never called), then `spec.decide` with `taskId` = the SDK `agentID` (a throw is a deny).
- **Floor** (`floor/`, moved from `src/`): OS sandbox builder, env scrub and deny list, sensitive paths, path helpers, sandbox errors. Safety floor = code, not data. Old `src/` paths re-export them until plan 6.
- **Not verified live:** that `agentID` equals the `task_id` of `task_started`; that the session id stays the same after `resume`; background tasks under a long-lived session. Check with `scripts/smoke-runtime-claude.ts`.

## `packages/surface-discord` and `apps/friday` (plan 5)
`Surface` on Discord, and the composition root. Only `src/discord-js-port.ts` and `src/private-overwrites.ts` import `discord.js` (`packages/surface-discord/test/boundary.test.ts`); everything else talks to the `DiscordPort` interface, which tests fake.
- **Channels:** one private channel per bot and per group under a `Friday` category (the category is found by name, created once). The topic `friday:bot:<id>` / `friday:group:<id>` is the mapping; the channel id is the conversation id. `syncChannels` reuses a channel by topic, creates the missing ones (a failure on one is reported, the rest go on) and leaves channels of removed bots alone. Private = `@everyone` cannot view; the owner and the app can.
- **Messages:** only the owner's non-empty messages in mapped channels count; bots and webhooks are ignored. Bot text goes out through one webhook per channel (named `Friday`, cached) under the bot's name; system text and long text are split at 2000 chars (line, then space, then hard cut). Typing is shown while a bot works.
- **Approvals:** a card with buttons `Allow once`, `Always allow` (omitted for irreversible tools), `Deny`; only the owner's click on an open card of that channel settles it, the card is edited with the answer and loses its buttons. Open cards are cancelled on stop.
- **Commands:** guild slash commands `/status`, `/stop [bot]` and `/purge` (empties the trash), owner only. `/stop` without a name stops the channel's bot (or every member of a group).
- **App (`startApp`):** loads `FileConfig` (defaults + `<AGENT_HOME>/config`), opens `<AGENT_HOME>/data/engine.db`, builds the surface, `PermissionGate` and `BotHub`, syncs channels (new channels get `Ready. Talk to me here.` / `Group ready: @A, @B`), watches the config dir: a changed or removed bot is stopped and its stored session id cleared (fresh session on its next message), then the channels are synced again, so a new bot or group gets a channel without a restart. A sweep every 60 s closes idle sessions. Sync and reload errors are logged, never thrown.
- **Friday bot:** shipped as a default bot file; it writes bot and group files into the config dir after the owner says yes in chat, and reads three group templates (`code`, `social-content`, `research`) in `packages/config/templates/`. `ClaudeRuntimeConfig.extraDirsFor(bot)` grants that bot (only) write on `config/bots` and `config/groups` (not `settings.yaml` or `tools.yaml`, the permission policy) and read on the templates; a user bot file with the id `friday` is refused, `friday` cannot be a group member, and the shipped bot runs at autonomy `careful` (its writes ask the owner with a card); the rest of `AGENT_HOME` stays denied by the floor.
- **`AGENT_HOME` layout:** `config/` (bots, groups, settings, tools, mcp), `data/engine.db`, `memory/{bots,groups}/<id>/`, `trash/<botId>/<stamp>/`, `scratch/<botId>/`, plus the old infrastructure (`data/agent.db`, `logs/`).
- **Not verified live:** the whole Discord path, the Friday bot flow, the templates' hand-offs. Checklist: [discord-setup.md](discord-setup.md).

## `packages/tools` (plan 6)
Built-in tools as in-process MCP servers, built per session. Imports only core, the SDK, zod and node; no env, no `console` (`packages/tools/test/boundary.test.ts`).
- **Memory files** (`memory/file-memory.ts`, `FileMemory` = the core `Memory` port): `<AGENT_HOME>/memory/bots/<id>/MEMORY.md` and `groups/<id>/MEMORY.md`, sections Decisions, Facts, Preferences, Lessons; one note per bullet, sanitized and deduplicated, file lock and atomic write, an edit backs the file up first (newest 20 in `backups/`).
- **Injection:** `BotHubDeps.memory`: the pool reads the bot's file when a session opens (`BotRuntimeSpec.memory`, appended to the system prompt as `## Your memory`); on a group turn the hub sends the group's file (`InboundTurn.groupMemory`, printed as `Group memory:` before the recent messages) only when it changed since that session last got it. A read failure sends nothing and never blocks the turn.
- **Tools** (`memory` server): `MemorySave` (note, kind, scope `bot` | `group`), `MemoryEdit` (list ids, replace, delete), `MemorySearch` (plain words over `MEMORY.md` then the journals, newest first). Group scope only from a group conversation the bot is a member of (`ToolSessionContext.conversation()` follows `spec.currentConversation()`).
- **Journal and flush:** `journal/<YYYY-MM-DD>.md` per owner (300 lines a day, pruned after 30 days, at start and daily). After the SDK compacts a bot's main thread, `ClaudeRuntimeConfig.onCompact` hands the summary to `extractNotes` (one Haiku call, no tools, at most 5 notes) and the notes go into today's journal as a `Flush` block, never into `MEMORY.md`; it never delays the bot.
- **Effects** (`effects` server, only for a bot that names one of its tools): `DeletePaths` (to `<AGENT_HOME>/trash/<botId>/<stamp>/`, 7 days, every path checked first: absolute, real path strictly inside a workspace, no `.git`, not sensitive; one refusal moves nothing), `GitPush` (`git push <remote> <b>:<b>`, never forced), `CreatePullRequest` (`gh pr create`), `MergeBranch` (refuses a dirty worktree, aborts a conflict), `CreateProject` (`git init` under `projectsDir`; the Friday bot only). Names must be plain (`isPlainName`); commands run as argv, no shell, with a minimal env (PATH, HOME, ssh agent, gh token); git runs with hooks off and refuses a repo whose local config sets a key that runs a program (fsmonitor, filters, merge drivers, sshCommand, includes...). A bot gets only the effect tools it names (`mcp__effects` = all). A dir is deleted only when nothing inside is sensitive or a nested repo. A background task cannot use group scope while the bot answers another conversation; after a compaction the group memory is sent again. Annotations in `tools.yaml` decide asking: `DeletePaths` and `MergeBranch` destructive, `GitPush` and `CreatePullRequest` open-world.
- **External MCP servers** are data (`mcp.yaml`, stdio or http, `${NAME}` from the env); a bot names their tools as `mcp__<server>__<tool>` and the runtime denies any MCP tool a bot does not name.
- **Not verified live:** the flush, the effect tools, Playwright through the new engine.
